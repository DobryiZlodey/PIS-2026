## Ход выполнения работы

### 1. Команды (Commands)

**Созданные команды:**

1. **CreatePortfolioCommand** - Создать новый портфель инвестиций
   - Поля: `portfolio_id: str`, `owner_id: str`
   - Валидация: Строки не должны быть пустыми.
   - Файл: `application/command/create_portfolio_command.py`

2. **AddTransactionCommand** - Добавить сделку (покупка/продажа)
   - Поля: `portfolio_id`, `ticker`, `type`, `quantity`, `price`, `currency`
   - Валидация: Тикер 1-5 символов, Количество > 0, Цена >= 0, Валюта из 3 букв.
   - Файл: `application/command/add_transaction_command.py`
   
3. **ClosePortfolioCommand** - Закрыть портфель
   - Поля: `portfolio_id`
   - Валидация: Не пустая строка
   - Файл: `application/command/close_portfolio_command.py`

**Пример кода команды:**
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class CreatePortfolioCommand:
    """Command: Создать новый портфель инвестиций"""
    
    portfolio_id: str
    owner_id: str
    
    def __post_init__(self):
        if not self.portfolio_id or not isinstance(self.portfolio_id, str):
            raise ValueError("portfolio_id must be a non-empty string")
        if not self.owner_id or not isinstance(self.owner_id, str):
            raise ValueError("owner_id must be a non-empty string")
```

### 2. Command Handlers

**Созданные обработчики:**

1. **CreatePortfolioHandler** - Создает агрегат Portfolio
   - Шаги обработки: Инициализация Portfolio через конструктор (инварианты проверяются внутри), сохранение через `PortfolioRepository.save()`.
   - Возвращает: `portfolio_id`
   - Файл: `application/command/handlers/create_portfolio_handler.py`

2. **AddTransactionHandler** - Обрабатывает сделку
   - Шаги: Загружает Portfolio по ID из `PortfolioRepository`, вызывает `portfolio.add_transaction()`, сохраняет состояние.
   - Возвращает: `transaction_id`
   - Файл: `application/command/handlers/add_transaction_handler.py`
   
3. **ClosePortfolioHandler** - Закрывает портфель
   - Шаги: Получает Portfolio, вызывает `close()`, сохраняет состояние.
   - Возвращает: `None`
   - Файл: `application/command/handlers/close_portfolio_handler.py`

**Пример кода handler:**
```python
class AddTransactionHandler:
    
    def __init__(self, repository):
        self.repository = repository
        
    def handle(self, command: AddTransactionCommand) -> str:
        # Load from repo
        portfolio = self.repository.find_by_id(command.portfolio_id)
        if not portfolio:
            raise ValueError(f"Portfolio {command.portfolio_id} not found")
            
        # Execute business logic on the aggregate
        tx_id = portfolio.add_transaction(
            ticker_str=command.ticker,
            type_name=command.type,
            quantity_val=command.quantity,
            price_val=command.price,
            currency=command.currency
        )
        
        # Save changes
        self.repository.save(portfolio)
        
        return tx_id
```

class GetPortfolioByIdHandler:

                currency=pos.average_price.currency
            ))
            
        transactions_dto = []
        # ... logic conversion ...
            
        return PortfolioDto(
            id=portfolio.id,
            owner_id=portfolio._owner_id,
            status=portfolio.status,
            positions=positions_dto,
            transactions=transactions_dto
        )

## Контрольные вопросы

1. **В чём разница между Command и Query?**
   - Command используется для мутации системы, оно модифицирует данные (или пытается это сделать), в то время как Query возвращает проекцию или часть данных без изменения состояния системы.

2. **Почему Command Handler возвращает только ID, а не весь объект?**
   - Для того, чтобы не привязывать мутирующие операции к логике чтения, и для предотвращения утечки логики домена клиентам. Клиент должен сделать Query-запрос для получения полных обновлённых данных.

3. **Где должна выполняться валидация: в команде, обработчике или доменной модели?**
   - Валидация примитивных типов и форматов происходит в самой Команде. Бизнес-валидация (инварианты домена) выполняется глубоко внутри доменной модели.

4. **Можно ли вызывать Query из Command Handler?**
   - Нежелательно. Обработчик команд выполняет лишь изменения состояния. Для запроса данных необходимо использовать Query извне.

5. **Зачем разделять Request DTO (от клиента) и Command (внутренний)?**
   - DTO служит контрактом между внешним миром (API, REST/JSON) и приложением. Command представляет собой чистое намерение для Application Layer. Это позволяет менять HTTP JSON входы без изменения структуры Commands.
