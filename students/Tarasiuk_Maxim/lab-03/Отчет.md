## Ход выполнения работы

### 1. Value Objects (Ценностные Объекты)

**Созданные Value Objects:**

1. **Money** - финансовая величина (сумма, валюта).
   - Валидация: Валюта должна быть трехсимвольной, сумма не отрицательная. Сложение и вычитание только для одной валюты.
   - Иммутабельность: ✅
   - Файл: `domain/value_objects/money.py`

2. **Ticker** - биржевой тикер ценной бумаги.
   - Валидация: 1-5 символов, только латинские заглавные буквы.
   - Иммутабельность: ✅
   - Файл: `domain/value_objects/ticker.py`

3. **Quantity** - количество акций.
   - Валидация: Строго целое число больше нуля.
   - Иммутабельность: ✅
   - Файл: `domain/value_objects/quantity.py`

4. **TransactionType** - тип операции `BUY` или `SELL`.
   - Валидация: Ограничено значениями Enum.
   - Иммутабельность: ✅
   - Файл: `domain/value_objects/transaction_type.py`

**Пример кода (Quantity)**:
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Quantity:
    """Value Object: Количество ценных бумаг"""
    
    value: int
    
    def __post_init__(self):
        if not isinstance(self.value, int):
            raise ValueError("Quantity must be an integer")
        if self.value <= 0:
            raise ValueError(f"Quantity must be greater than zero: {self.value}")
```

### 2. Entities (Сущности)

**Созданные Entity:**

1. **Position** - позиция по определённой ценной бумаге в портфеле.
   - ID поле: `_id` (генерируется как комбинация тикера и портфеля)
   - Бизнес-правила: При покупке пересчитывается средняя цена активов, при продаже количество уменьшается.
   - Файл: `domain/entities/position.py`

2. **Transaction** - история операции.
   - ID поле: `_id` 
   - Бизнес-правила: Отражает неизменяемый исторический факт, но имеет ID для дедупликации и связи со сторонними системами (брокером).
   - Файл: `domain/entities/transaction.py`

**Пример кода (Position)**:
```python
class Position:
    def add_shares(self, quantity: Quantity, price: Money) -> None:
        """Добавить акции к позиции (покупка) и пересчитать среднюю цену"""
        if self._is_empty:
            self._quantity = quantity
            self._average_price = price
            self._is_empty = False
        else:
            if self._average_price.currency != price.currency:
                raise ValueError("Currency mismatch")
            
            total_value_old = self._quantity.value * self._average_price.amount
            total_value_new = quantity.value * price.amount
            new_total_quantity = self._quantity.value + quantity.value
            new_avg_price = (total_value_old + total_value_new) / new_total_quantity
            
            self._quantity = Quantity(new_total_quantity)
            self._average_price = Money(new_avg_price, price.currency)
```

### 3. Aggregate Root (Корневой агрегат)

**Aggregate Root:** Portfolio

**Границы агрегата:**
- Корень: `Portfolio`
- Внутренние сущности: `Position`, `Transaction`
- Value Objects: `Money`, `Ticker`, `Quantity`, `TransactionType`

**Инварианты агрегата:**

| № | Инвариант | Как проверяется |
|---|----------|----------------|
| 1 | Транзакцию можно добавить только в ACTIVE портфель | `if self._status != "ACTIVE"` в `add_transaction()` |
| 2 | Нельзя продать (SELL) актив, которого нет в портфеле | Проверка наличия тикера в `self._positions` |
| 3 | Нельзя продать больше, чем есть | `if pos.quantity.value < quantity.value` |
| 4 | Нельзя закрыть закрытый портфель | `if self._status == "CLOSED"` в `close()` |

**Пример кода Aggregate Root:**
```python
    def add_transaction(self, ticker_str: str, type_name: str, quantity_val: int, price_val: float, currency: str) -> str:
        """Регистрирует транзакцию купли-продажи (инварианты проверяются)"""
        
        if self._status != "ACTIVE":
            raise ValueError("Cannot add transaction to a non-active portfolio")
            
        ticker = Ticker(ticker_str)
        quantity = Quantity(quantity_val)
        price = Money(price_val, currency)
        
        trx_type = TransactionType(type_name)
        
        # Invariant checks for SELL
        if trx_type == TransactionType.SELL:
            if ticker.symbol not in self._positions:
                raise ValueError(f"Cannot sell {ticker.symbol}: position does not exist")
                
            pos = self._positions[ticker.symbol]
            if pos.quantity.value < quantity.value:
                raise ValueError(f"Cannot sell {quantity.value} of {ticker.symbol}: only {pos.quantity.value} available")
```

**Созданные события:**

1. **PortfolioCreatedEvent** - сгенерировано в конструкторе портфеля.
   - Данные: `portfolio_id`, `owner_id`
   - Файл: `domain/events/portfolio_events.py`

2. **TransactionAddedEvent** - сгенерировано после успешного добавления сделки.
   - Данные: `portfolio_id`, `transaction_id`, `ticker_symbol`, `type_name`, `quantity`, `price`
   - Файл: `domain/events/portfolio_events.py`

3. **PortfolioClosedEvent** - сгенерировано после закрытия портфеля.
   - Данные: `portfolio_id`
   - Файл: `domain/events/portfolio_events.py`

**Пример кода события:**
```python
@dataclass
class TransactionAddedEvent(DomainEvent):
    portfolio_id: str
    transaction_id: str
    ticker_symbol: str
    type_name: str
    quantity_value: int
    price_amount: float
    _occurred_on: datetime = field(default_factory=datetime.now)

    def occurred_on(self) -> datetime:
        return self._occurred_on
```

## Контрольные вопросы

1. **В чём отличие Value Object от Entity?**
   - Entity имеет свою идентичность (ID) и жизненный цикл (состояние может меняться). Value Object иммутабелен (состояние не меняется после создания) и определяется исключительно значениями его атрибутов (например, 100 USD всегда равно 100 USD вне зависимости от экземпляра класса).

2. **Почему Aggregate Root должен инкапсулировать доступ к внутренним сущностям?**
   - Для сохранения бизнес-инвариантов. Внешние классы не должны иметь возможность изменить сущность `Position` в обход бизнес-логики `Portfolio` (например, продать акции, когда портфель закрыт), поэтому агрегат действует как точка входа и гарант целостности данных.

3. **Какая роль Domain Events? Приведите пример из вашей системы.**
   - Domain Events уведомляют внешние системы (или другие ограниченные контексты) об изменениях в агрегате. Пример: `PortfolioClosedEvent`. Приложение может слушать это событие для формирования отчетов или закрытия счетов на стороне брокера.

4. **Как вы проверяете инварианты в вашем агрегате? Приведите пример.**
   - Инварианты проверяются в методах, манипулирующих состоянием - выкидываются `ValueError`. Например, в `add_transaction` есть проверка, что количество продаваемых акций не превышает их количество в позиции.

5. **Почему Value Objects делаются иммутабельными?**
   - Это гарантирует потокобезопасность и предсказуемость кода. Если у нас есть цена акций (Money) и её передали в другую функцию, мы должны быть уверены, что её случайно не изменят по ссылке, испортив данные в изначальных расчетах.
