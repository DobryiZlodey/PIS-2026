### Часть 3. Domain Layer (Доменный слой)

#### Доменные сущности

**Entity 1**: Portfolio

```python
class Portfolio:
    """Доменная модель: Портфель инвестора"""
    
    def __init__(self, portfolio_id: str, owner_id: str):
        self.id = portfolio_id
        self.owner_id = owner_id
        self.positions = []
        self.transactions = []
        
    def add_position(self, position):
        self.positions.append(position)
```

**Value Object 1**: Position

```python
class Position:
    """Доменная модель: Позиция по ценной бумаге"""
    
    def __init__(self, ticker: str, amount: int, average_price: float):
        self.ticker = ticker
        self.amount = amount
        self.average_price = average_price
```

#### Бизнес-правила

1. Портфель содержит уникальные позиции по тикерам.
2. Цена сделки и средняя цена покупки не могут быть отрицательными.
3. Расчет доходности изолирован от способа получения котировок (цены подаются на вход метода доменной модели как параметры).

        self.portfolios = {}
        
    def save(self, portfolio) -> None:
        self.portfolios[portfolio.id] = portfolio
        
    def find_by_id(self, portfolio_id: str):
        return self.portfolios.get(portfolio_id)

## 6. Выводы

### Что получилось хорошо

Удалось четко разделить логику управления портфелем от инфраструктурных моментов (БД и HTTP запросов). 
Центральный слой (домен) остается абсолютно чистым и содержит только бизнес-логику расчетов. 

### С какими трудностями столкнулись

На этапе проектирования было необходимо строго отделить порт-интерфейс `MarketDataService` от его реализации (парсера внешних страниц или REST-клиента). Использование абстракций решает эту проблему.

### Что узнали нового

На практике применил принцип Dependency Inversion: доменный и прикладной слой не зависят от деталей реализации инфраструктуры. Все зависимости инжектятся через DI-контейнер при запуске приложения.
